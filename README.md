## 🧠 開發思維與技術挑戰

### 1. 狀態管理策略：為什麼選擇 Redux Toolkit (RTK)？

在開發 La Nuit Puff 這種具備完整購物與後台管理邏輯的專案時，我面臨了大量跨組件狀態（如購物車同步、管理員登入狀態）的傳遞挑戰。

**決策理由：** 雖然 Context API 能處理全局狀態，但考量到電商系統狀態更新頻繁且邏輯複雜，為了避免不必要的組件重新渲染（Re-render）並提升可維護性，我選擇了 Redux Toolkit。

**實踐細節：** 我利用 createAsyncThunk 整合 Axios 處理非同步資料流，實現了資料邏輯與 UI 視圖的解耦，這讓我在後續擴充「訂單狀態管理」時更加高效。

### 2. 敏捷開發與 AI 協作經驗

本專案開發過程中，我將 AI 工具定義為「技術顧問」，以加速從平面設計轉向網頁開發的過程：

**技術可行性評估：** 在開發初期，我會針對複雜功能（如資料庫連線或狀態整合）諮詢 AI，確認技術選型（如選用 RTK 的優勢）是否符合專案需求，這幫助我能快速定案開發方向。

**迭代開發思維：** 我採取「先求有再求好」的策略，先設計核心功能的原型，再透過 AI 協助除錯或詢問使用者體驗來優化架構。

### 3. 從設計到開發的橋樑（設計師優勢）

身為平面設計師轉職者，我專注於減少設計稿與程式碼之間的落差：

**視覺精準度：** 利用 Figma 進行視覺規劃，並透過 SCSS 系統化管理變數（如品牌色、字級），確保開發產出高度還原設計稿。

**組件化思考：** 在規劃 React 架構時，我將設計上的「重複元素」對應為「可重用組件」，在維持視覺一致性的同時也提升了代碼的複用性。

## ✨ 核心功能

### 👩‍💼 後台管理系統

- **商品管理** - 新增、編輯、刪除、啟用/停用商品
- **訂單管理** - 查看訂單、編輯狀態、刪除訂單
- **文章發佈** - 發表關於我們的文章和新聞
- **圖片上傳** - 支援圖片上傳與 URL 管理

### 🛍️ 前台購物系統

- **商品瀏覽** - 分類篩選、排序、檢視詳情
- **購物車** - 新增商品、調整數量、移除項目
- **結帳系統** - 訂單確認、填入收貨資訊
- **會員功能** - 登入、訂單紀錄、收藏商品
- **品牌介紹** - 關於我們、產品特色、文章閱讀
